# 系统架构

## 1. 形式内核

`metamath_generator.parser` 解析 `$c`、`$v`、`$f`、`$e`、`$d`、`$a`
和 `$p`，并将断言分为：

- 语法规则：产生 `term`、`wff` 等类型；
- 逻辑断言：产生 `|- ...`；
- `statement`：只命名目标公式，不声明其为真。

`Node` 是统一的不可变前缀 AST。`Theorem` 保存开放前提、结论、变量类型、
distinct-variable 约束和证明 DAG，并将定理陈述变量与只供证明回放使用的
内部变量分开保存。

## 2. 证明组合

组合器将规则的部分前提与已有证明对象的结论同时合一。被匹配父定理的开放
前提与未匹配规则前提共同进入新对象：

```text
Γ ⊢ A      Δ ⊢ A → B
--------------------
       Γ, Δ ⊢ B
```

所有替换执行 occurs check、精确类型检查和 `$d` 检查。规则变量在应用前
standardize apart，避免与目标变量意外捕获。

## 3. 质量控制

`TheoremGenerator` 维护活动候选、被支配对象和隔离 proof states：

- 语义规范化只用于比较，不改写证明公式；
- 拒绝生成的真空量词和裸模式结论；
- 对相同规范化结论执行前提集合与 `$d` subsumption；
- 奖励闭合、非平凡、含算术结构且证明深度适中的对象；
- 限制连续 alpha 规则和同结论低质量状态数量。

## 4. 神经符号证明

形式 tokenizer 对每个 Metamath 符号和控制指令使用一个原子 token。
Transformer 编码证明状态，并自回归预测规则与显式替换；价值头估计状态
可解性。

混合搜索包含三类候选：

1. 传统证明器枚举的合法规则应用；
2. 由已知定理子结构提出的辅助引理；
3. Transformer 排序或生成的候选动作。

PUCT/MCTS 搜索 AND 型多子目标树。只有最终解路径获得正价值监督，旁支搜索
不会被错误标成成功。

## 5. 证书与验证

搜索动作首先在 `BackwardEnvironment` 中执行。成功路径随后编译为证明
证书，并由项目内 Metamath 验证器按声明顺序和活动作用域重放。模型权重、
MCTS 统计和启发式都不属于符号验证边界。当前内核仅支持未压缩证明；重要
证书仍应由外部 Metamath 实现交叉验证。

## 6. Scale 管线

Scale 数据由已经验证的基础证明模板进行类型保持实例化：

- `term` 变量替换为随机自然数项；
- `wff` 变量替换为随机良构公式；
- 操作符元变量替换为同类型具体操作符；
- 对象变量保持对象变量类型；
- 重新计算 `$d` 约束。

生成器以 gzip JSONL 分片写入，保存候选游标以支持恢复，并在写入层对
state/action ID 进行跨 split 全局去重。训练器支持 bf16、梯度累积、逐层
梯度检查点、上下文课程、周期检查点和精确断点恢复；检查点包含数据流游标、
Python/PyTorch RNG 状态、scheduler、累计计数和完整 metrics 历史。
