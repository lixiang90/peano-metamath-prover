# 定理库增长与采样改进路线

记录日期：2026-10-10。代码基线：`ebf7a49`。

本文记录默认 `graph` 模式的当前行为、规模扩大后的限制，以及后续可逐项实施和评估的
改进方案。下文的改进均未实现，建议比例也不是已经测得的最优参数。
结构预筛选漏采样已在基线中修复，不再列入待办；修复和验证记录见
[随机证明图生成](random-proof-graphs.md)。本文不修改生成、训练或推理行为。

## 1. 当前采样机制

| 环节 | 当前行为 | 配置或实现位置 |
| --- | --- | --- |
| 生成操作 | 默认 90% 组合、10% 小表达式实例化 | `graph_instance_probability=0.10` |
| 规则来源 | 有符合深度限制的派生规则时，25% 选择派生规则，75% 选择源规则；派生规则需要有前提 | `graph_derived_rule_probability=0.25` |
| 规则权重 | 在选中的规则池内，按 `(1 + 选择次数)^(-0.5)` 加权 | `graph_rule_bias=0.5` |
| 主动保留前提 | 多前提规则有 30% 概率保留一个前提；单前提规则仍需接入父节点 | `graph_partial_premise_probability=0.30` |
| 匹配顺序 | 先处理固定结构较多的前提 | `RandomProofGraph.combine()` |
| 候选检索 | 对每个待匹配前提扫描整个 store，排除达到深度上限的节点，再进行结构预筛选 | `RandomProofGraph.candidates()` |
| 深度采样 | 对非空兼容候选桶，按 `(depth + 1)^0.5` 选择深度桶 | `graph_depth_bias=0.5` |
| 桶内采样 | 按 `1 / sqrt(1 + parent_uses[id])` 选择节点，在本次候选列表中不重复选择 | `RandomProofGraph.candidates()` |
| 候选预算 | 每个前提最多列出 24 个候选；接受第一个组合成功且满足结构限制的候选 | `graph_match_candidates=24` |
| 存储 | alpha 归一化声明哈希去重；所有入库图节点保留，质量分数只作诊断 | `RandomProofGraph.admit()`、`TheoremDatabase.add()` |

对应代码：[采样器](../src/metamath_generator/random_graph.py)、
[参数定义及生成入口](../src/metamath_generator/generator.py)、
[定理存储](../src/metamath_generator/database.py)、
[合成内核](../src/metamath_generator/compose.py)。

理解这些参数时需要区分：

- 25% 是规则来源池的概率，不是某条派生规则的概率；同一池中还有选择次数权重。
- 深度桶的概率不乘桶内节点数，因此大量浅层节点不会仅靠数量占据全部候选机会。
  同一深度内仍可能出现相似公式过多的问题。
- `rule_attempts` 在规则被选中时增加，即使最终没有生成新定理。
  `parent_uses` 只在新定理成功入库时更新，计入其证明依赖；不表示候选尝试次数、失败次数，
  也不等价于只统计“作为前提”的使用次数，因为派生规则本身也是证明依赖。
- 源规则和父节点的采样不是均匀全库随机；现有规则复用和父节点复用都采用降权。
- AST 大小、变量数量、假设数量和证明深度仍有限制。没有工作池节点数或字节数的独立预算。
- `graph_depth_bias` 与旧算法的 `depth_parent_bias` 是不同参数。旧 `random` 模式的质量权重、
  闭合父节点偏好等，不应被当成默认 `graph` 模式正在使用的策略。

## 2. 定理库在哪里增长、在哪里重置

| 入口 | 定理库生命周期 | 是否跨批次积累生成定理 |
| --- | --- | --- |
| 原始 `graph` 生成 | 一次生成器运行内持续增长；调用者也可以继续使用同一个生成器 | 单次运行内可以；采样统计另有重置问题 |
| v1 `build-corpus` | 每个种子创建新的生成器 | 不同种子之间不共享生成定理 |
| HTPS 图语料 | 使用共享的 v1 图语料构建流程 | 同上 |
| Scale 图语料 | 默认每批 `graph_steps=200`，每批创建新的生成器 | 不共享历史图节点，只保留训练记录和去重信息 |
| v2 语料 | 每个种子独立生成，再生成完整证书和 Agent 轨迹 | 后续检索库没有反馈给本阶段的生成器 |

对应代码：[v1](../src/neural_prover/data.py)、[HTPS](../src/htps_prover/graph_data.py)、
[Scale](../src/neural_prover/graph_scale.py)、[Scale 默认配置](../src/neural_prover/scale_data.py)、
[v2](../v2/pa_prover_v2/data.py)。

因此，目前扩大 Scale 语料数量，不会让所有历史定理进入同一个越来越大的父节点池。
这限制了单图采样开销，也限制了跨批次知识积累。Scale 的全局样本 ID 去重集合仍随语料
数量增长，不能据此认为整个语料生成流程的内存恒定。

v2 的 `TheoremLibrary` 是另一个对象：它在证书生成和数据分组之后构造，用于检索和
Agent 轨迹增强。它具有条数与字节预算，但尚不是随机生成器的历史父节点库。
未来接入时需要显式建立反馈路径，不能仅因存在 `library.json` 就认为已实现持续积累。

## 3. 当前限制与已有测量

### 3.1 后续前提没有利用当前替换缩小检索范围

`compose()` 已经把所选父节点放在同一个合一过程中处理；问题在候选检索阶段。
例如前提 `A(x)` 已得到替换 `x=t`，后续前提仍按原始 `B(x)` 检索，而没有先按 `B(t)`
筛选候选。无关节点可以消耗固定的 24 个候选名额。

匹配同时采用贪心策略：前一前提一旦接受某个父节点，后续失败不会回头更换它。
因此，已有可用组合也可能未被发现。未匹配前提会成为开放假设；这部分应与有意保留
新前提的采样机制分别评价，不能仅看最终有多少带前提定理。

### 3.2 当前权重没有区分多样性与长期价值

深度分桶保护了深层节点的采样机会，但没有结构族、假设数量和新旧节点的独立配额。
声明级去重不等于结构族均衡：大量相近实例或不同假设变体仍可能占据同一桶。

复用降权增加探索，同时可能降低通用引理的使用机会。生成很多非重复后继、帮助不同
证明分支的引理，和反复产生同类结果的引理，现在没有按实际贡献区别对待。
候选失败或产生重复结果也没有独立的成本统计供采样器利用。

### 3.3 索引与加权采样仍随库大小增长

每次父节点检索都扫描全库、重建候选桶；在桶内逐次抽样时又重新计算权重。
选择派生规则或实例化对象也会重新遍历生成节点。24 个候选限制的是后续尝试数量，
没有把前置全库检索变成常数开销。

若每步持续保留新节点，在表达式大小等因素受限时，累计扫描工作量可能接近平方增长。
实际总耗时还受合一、类型检查、假设合并和证明处理影响，不能仅凭这一复杂度推断瓶颈。

2026-10-10 修复预筛选前，在 `3378680` 上做过一次只在内存中运行的诊断：PA+、种子 7、
深度上限 12、其余图参数采用默认值。使用同一个 `RandomProofGraph` 实例连续运行
1,000 步，每 250 步记录一次；没有在窗口之间重建采样器。

| 窗口 | 窗口末 store 节点数 | 每次候选检索平均扫描节点数 | 每次候选检索平均耗时 | 检索占窗口总耗时 |
| --- | ---: | ---: | ---: | ---: |
| 第 1–250 步 | 286 | 211 | 约 0.29 ms | 约 4.6% |
| 第 751–1000 步 | 685 | 612 | 约 0.90 ms | 约 8.3% |

这些数值是单种子、千步规模的历史观测，原始输出保留在会话中，没有作为基准数据文件
提交。它们说明检索开销随库增长，但不足以证明检索当时已是主瓶颈。预筛选修复后候选
集合与随机序列已经变化；后续比较应在当前基线上重新测量，不能把此表作为修复后的性能。

### 3.4 同一生成器重复调用时会丢失采样历史

每次调用 `generate("graph", ...)` 都会新建 `RandomProofGraph`，其 `rule_attempts` 和
`parent_uses` 从零开始。store 可以继续增长，但采样历史没有随之保留；
`graph_reused_parents` 和 `graph_parent_edges` 也由本次采样器的局部计数覆盖。
连续生成和断点恢复设计应同时保存节点、采样状态和统计口径。

## 4. 后续改进顺序与验收条件

以下各项均为待实施方案。保持已有采样策略作为对照，逐项加入，避免同时改变多个因素。

| 顺序 | 改动 | 最低验收条件 |
| --- | --- | --- |
| 1 | 条件化候选检索与有界回溯 | 能发现贪心漏掉的已知组合；总合一预算有界；主动保留比例含义不变 |
| 2 | 增量符号索引和采样数据结构 | 小库上与全扫描比较，不漏可合一候选；大库上减少扫描与权重重建成本 |
| 3 | 持久化采样历史、完整档案与有界工作池 | 跨批次复用引理且证书可完整重放；恢复与不中断运行保持一致 |
| 4 | 加入多样性和历史价值的混合采样 | 多种子下覆盖率、有效产出和复用分布改善，成本没有失控 |
| 5 | 训练与完整证明评测 | 在独立任务上检验收益，不以生成深度或单步准确率代替证明能力 |

### 4.1 条件化候选检索与有界回溯

保留当前规则、已匹配父节点和联合替换。查询下一个前提前先应用当前替换，并在统一的
标准化变量命名空间内继续合一；替换后仍含变量的子式应继续允许合法实例化。

可先实验每层保留 2–4 个替代匹配，但必须另设整次组合的总合一尝试预算。
多分支共享预算，不能让“每前提 24 个候选”悄然膨胀为所有候选的笛卡尔积。
主动保留的前提仍保持开放；匹配失败时再依据预算进行有限回溯。

验收用例应包含：第一个可行父节点导致后续冲突、更换父节点才能完全匹配；合一后
新假设与继承假设重合；跨父节点的 occurs check、类型和 `$d` 冲突；预算耗尽时能够
明确区分主动保留与未能完成匹配。

### 4.2 增量符号索引与权重维护

入库时维护固定主符号、元数、部分结构、深度和假设数量等索引。类型信息只能用于
有语法依据的排除，不能恢复“类型名不同就拒绝”的假设。索引必须保留叶变量和算子
变量的通配分支，并支持查询端、库节点端都可能被替换的双向合一。

先实施简单且容易验证的结构索引，再视规模考虑替换树等专门的 term indexing 方法。
减少索引维护之外的重复开销：增量维护派生规则列表、深度桶及权重；需要频繁改权重时，
可评估前缀和树等结构，避免每次选择都重算整个桶。

小库上用全扫描作为召回检查的参照；随机化有类型表达式测试中，任何被完整合一接受
的节点都不得被索引提前排除。允许保守地返回额外候选，最终仍由原内核检查。

### 4.3 完整证明档案与有界工作池

完整档案保存声明、假设、`$d`、形式系统指纹、来源、证明依赖和可重放证书。
日常采样使用另一个有节点数和字节预算的工作池，定期从档案补充；退出工作池不应删除
已有证明依赖，也不意味着该引理失效。不同采样视图可以引用同一份不可变证书。

批次间携带经过验证的历史引理、随机数状态、采样计数和工作池版本。Scale 的恢复标识
需要覆盖算法版本、档案快照、池成员与采样状态；仅记录原来的图编号和图内游标不够。
所有字典、候选列表和序列化顺序应具有确定性。

引理重新进入工作池时保留完整证明依赖深度、展开证书成本，并可另记当前生成段的扩展
深度。压缩后的调用步数和完整证明深度分别报告；不能把派生引理转成新公理或通过清零
历史深度绕开预算。若长期积累触及现有深度上限，应显式调整课程和展开预算。

生成用历史库应按数据划分和可用时间约束访问。尤其不能把验证/测试目标的证书或其解答
反馈到训练生成过程；v2 当前的训练来源和目标排除检查需要延续到新反馈路径中。

### 4.4 混合采样与引理价值

在已经满足结构检索条件的候选中，以下混合比例可作为第一组实验：

| 通道 | 试验比例 | 目的 |
| --- | ---: | --- |
| 最近新增节点 | 40% | 给新结果继续生长的机会 |
| 结构族、深度和假设数量均衡 | 30% | 减少相近公式和大桶对少数结构的稀释 |
| 历史上能产生有效新结论的引理 | 20% | 保留可复用的通用工具 |
| 广泛随机探索 | 10% | 给尚无使用记录的历史节点机会 |

这是采样通道的混合，不要求四个候选集合互斥。需要规定空通道的回退行为，并记录
实际通道比例。应先保持源规则/派生规则的 75:25 配置作对照，再单独实验该比例。
这些新参数目前没有实现，不能作为现有 CLI 参数使用。

引理价值可参考：单位尝试或 CPU 时间产生的非重复后继数量、被不同结构族的后续证明
使用的情况、展开证明步骤的实际节省，以及证书和上下文成本。区分候选曝光、被尝试、
合一成功、入库成功、后继复用几个事件，不把当前 `parent_uses` 直接当作价值标签。
失败记录也应区分语法不兼容、当前上下文冲突、重复结果和资源耗尽。

保持探索概率，避免纯价值排序锁定早期赢家；也避免只奖励公式长度、证明深度或简单
的使用次数。结构族限额优先影响采样配额，不应自动删掉有效的中间证明节点。

## 5. 后续实验与记录要求

先补齐可观测性，再比较方案。已有图统计见 [生成算法说明](random-proof-graphs.md)。
`graph_unmatched_after_search` 目前只统计入库组合中的未匹配槽位，不能代表所有失败
尝试；`graph_reused_parents` 也不能代替完整的复用分布。

| 维度 | 建议记录 |
| --- | --- |
| 成本 | 检索、合一、类型检查、入库、证书展开各阶段耗时；每秒新增定理数；档案和工作池字节数 |
| 召回与匹配 | 每次查询扫描/返回/尝试节点数；合一成功率；预算耗尽次数；全扫描对照下的漏召回数 |
| 开放前提 | 主动保留与搜索未匹配分别计数；原始前提槽位数、最终新假设数和继承假设数分别报告 |
| 多样性 | 声明去重率、结构族覆盖、闭合/开放定理比例、假设数量和证明深度分布 |
| 积累与复用 | 父节点年龄、历史批次来源、未被使用节点比例、重复使用集中度、跨结构族复用 |
| 训练可用性 | 编码、长度、证书和上下文预算造成的过滤率；实际进入训练集的分布 |
| 证明能力 | 固定搜索预算下独立完整证明任务的成功率及官方验证结果 |

建议比较：当前基线、仅条件化检索、再加有界回溯、再加索引、再加跨批次工作池、最后
再加混合采样。使用相同的 PA+ 形式系统、种子集合和结构上限，同时报告等时间预算与
等合一尝试预算两种结果。大库检索基准可以逐步测到千、万、十万节点，但必须和实际
可验证图生成的端到端结果分开，不能用大量复制节点制造虚假的多样性收益。

每次实验保存代码提交、算法版本、完整配置、随机数状态或可复现种子、形式系统指纹、
库快照标识、分阶段原始计数和验证日志。训练数据分布发生变化后，应重新生成语料并
重新评价完整证明能力，不能只凭图变深或合成吞吐提高判定模型能力提升。
