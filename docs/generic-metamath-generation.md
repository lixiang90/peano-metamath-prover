# 通用 Metamath 随机生成器（备用）

记录日期：2026-10-10。算法标识：`generic-token-forward-v1`。

通过 `metamath-generate --mode generic` 或 `python -m metamath_generator --mode generic`
显式选择本算法。默认仍为 `graph`；v1、HTPS、Scale、v2 的默认生成和训练流程均不改变。
这是独立的符号串后端，没有调用 PA+ 的 AST 解析器、表达式采样器或质量筛选器。

## 依据与适用范围

设计依据是官方提供的 [mmverify.py](https://us.metamath.org/downloads/mmverify.py)
和 [Metamath 语言规范](https://us.metamath.org/downloads/metamath.pdf)第 4.1 节。
`mmverify.py` 是证明验证器；生成器反过来构造满足其栈操作和替换条件的推理步骤。
项目中的实现是独立编写的，不在运行时下载或执行该参考脚本。

通用后端只解释 Metamath 的 `$c/$v/$f/$e/$d/$a/$p`、作用域、文件包含和证明编码。
表达式始终是符号串，不假设存在 `|-`、`wff`、前缀语法、唯一语法分析或 PA 运算符。
支持空串替换，因此可处理 MIU 等不符合原 PA 语法假设的形式系统。
输入中的所有 `$p` 在进入规则库之前都要验证，包括压缩证明和保存子证明的 `Z` 编码。
未知、向前引用、失效作用域中的证明标签及不完整证明 `?` 会使加载失败，不作为公理跳过。

这里的“通用”指不依赖特定形式系统的表达式语法，**不代表对所有定理的完整或均匀采样**。
有限预算内不一定产生新结果；无推导空间或只有有限结论的系统尤其如此。
大数据库需要完整加载和检查，当前不提供流式索引或针对性加载。

与参考脚本的区别：

- 严格按声明顺序处理 mandatory hypotheses，包括 `$e` 后出现 `$f` 的合法情况。
  参考脚本开头注明了这方面的限制；这类测试以官方 C 程序的结果为准。
- 压缩证明直接重放表达式栈和保存结果，不将共享子证明展开成庞大的标签串。
- 包含文件按规范只加载一次，自引用被忽略。相对路径以包含它的文件所在目录为基准；
  规范没有统一目录约定，因此导出时会将所有包含文件展开成独立快照。

实现入口：[符号串解析与验证](../src/metamath_generator/token_mm.py)、
[随机采样](../src/metamath_generator/generic.py)、[CLI](../src/metamath_generator/cli.py)。

## 算法

1. 加载并验证源数据库，将 `$a` 和已验证的 `$p` 作为规则。新变量只声明 `$v/$f`，
   不添加新的 `$a`。按源规则需要的类型创建符号变量，并建立有限数量的恒等替换实例
   作为初始父节点；实例的必要前提仍保留为假设。
2. 在源规则和已生成规则之间采样，后者默认占 25% 的选择概率（需要已有结果）。
   在选中的库中，有前提/无前提规则默认按 75%/25% 选择；池为空时使用另一池。
   池内按 `1/sqrt(1+规则尝试次数)` 加权。无前提规则也用于构造替换所需的类型证明。
3. 对有前提规则，优先匹配固定符号较多的前提。多前提规则有 30% 概率主动保留一个
   前提，其余前提从相同首常量的已有节点中抽样。候选权重为
   `sqrt(depth+1)/sqrt(1+该结论被成功复用次数)`，每个前提最多 24 个候选。
4. 对规则前提和候选结论做有预算的符号串匹配。规则变量可以匹配连续符号串，也可以
   匹配空串；重复出现的变量必须得到相同替换。后续前提沿用前面得到的替换。
   这一轮匹配中，父节点内的变量作为固定符号；父节点以后作为派生规则时可再次实例化。
5. 每个替换 `x -> s` 都需要证明相应的 `$f`，例如 `type s`。优先检索已有证明；
   找不到时，在同首常量、无 `$e` 的规则上进行有限深度的反向构造。替换、类型证明
   搜索和候选匹配共享整次采样预算，不能只凭“看起来像合法表达式”接受替换。
6. 未被前提匹配约束的变量，通常补为对应类型的符号变量。默认 10% 概率尝试从已有
   同类型证明对象采样更一般的替换。这是一次组合的选择概率，不是每个变量独立的 10%。
7. 合并父节点及类型证明的假设，加入未匹配或主动保留的前提，逐对传播 `$d`。
   若要求相异的两份替换含相同变量，拒绝本次组合。有前提的规则至少匹配一个父节点。
8. 检查资源上限，按变量 alpha 归一化后的声明去重，并进行完整证明栈重放。
   成功后入库，后续可用该定理的 `$p` 标签及其 mandatory hypotheses 继续组合。

源规则实例仅用于启动采样，不算“新定理”。与源规则 alpha 等价的声明也不重复输出。
新定理是相对于本库未见的声明，并不意味着数学意义上的新发现。

`$d` 检查覆盖替换中全部变量的笛卡尔积；同一个变量不得出现在要求相异的两侧。
导出保留证明所需的 dummy-variable `$d`，但复用定理时只要求其 mandatory `$d`。
类型证明若依赖开放假设，这些假设也会进入最终声明，不被隐藏。

## 使用

已按项目安装说明执行可编辑安装后：

```bash
python -m metamath_generator formal/peano-pa-plus.mm --mode generic --steps 2000 --seed 7 --output-dir outputs/generic-pa-plus
```

直接从 Windows 源码目录运行时，可以先设置搜索路径：

```powershell
$env:PYTHONPATH='src;v2'
python -m metamath_generator formal/peano-pa-plus.mm --mode generic --steps 2000 --seed 7 --output-dir outputs/generic-pa-plus
```

将第一个参数替换为其他 `.mm` 文件即可。`--typecode "|-"` 仅筛选 JSONL 中输出的
声明类型，不删除证明依赖；其他系统可使用自己的首常量。默认输出全部类型，不会将
语法构造结果误报为特定系统的逻辑判断。

| 选项 | 默认值 | 含义 |
| --- | ---: | --- |
| `--steps` | 5000 | 尝试次数，不保证生成同样数量的新定理 |
| `--seed` | 7 | 随机种子 |
| `--max-tokens` | 192 | 每个结论/假设的符号数上限，包含首常量 |
| `--max-hypotheses` | 8 | 去重后的开放假设数上限 |
| `--max-variables` | 16 | 结论和假设中变量数上限 |
| `--max-proof-depth` | 8 | 相对源断言的证明深度保守上界 |
| `--max-proof-labels` | 4096 | 单个输出 `$p` 的直接证明标签数上限 |
| `--match-candidates` | 24 | 每个前提最多抽取的父节点数 |
| `--match-budget` | 4000 | 每次生成共享的匹配状态、类型查询和替换补全操作预算 |
| `--type-search-depth` | 6 | 反向寻找类型证明的递归深度 |
| `--seed-assertions` | 256 | 最多尝试多少个源规则的启动实例 |
| `--variables-per-type` | 4 | 每个类型至少分配的符号变量数；不足以表示源规则时自动增加 |
| `--max-pool-nodes` | 10000 | 父节点池条数上限，含符号变量和启动实例 |
| `--instance-probability` | 0.10 | 未绑定变量使用一般已有对象替换的尝试概率 |
| `--partial-premise-probability` | 0.30 | 多前提规则主动保留一个前提的概率 |

`--max-depth` 是旧后端的 AST 参数，在通用后端不适用；使用 `--max-tokens`。
通用后端不使用旧的质量、定义覆盖和目标引导参数；定义目录、定义启动和 DOT 导出会
明确报不支持。两类配置应分开记录。Python API 使用 `GenericConfig`，其中还可以设置
`derived_rule_probability`；同一个 `GenericGenerator` 连续调用 `generate()` 保留 RNG 和统计。

## 输出与证明边界

- `generated.mm`：包括已验证的源库快照和所有新增 `$p`，可单独交给官方程序验证。
  为避免源库末尾的全局 `$e/$d/$f` 污染新声明，源常量保留在外层，原声明包入一个已闭合
  作用域，再开始新声明。原注释和版权说明随源快照保留。
- `theorems.jsonl`：`metamath-token-theorem-v1` 格式，保存结论、假设、变量类型、
  mandatory `$d`、证明所需 `$d`、证明标签、应用规则和前提匹配统计。
  该记录需要配套 `.mm` 的声明和此前定理，不能脱离数据库单独重放。
- `summary.json`：算法版本、全部配置、展开源快照哈希、源证明验证数量、池大小、
  成功/失败计数和规则尝试次数。

没有复用旧 AST 语料格式。因此这份 JSONL **尚未接入 v1/HTPS/Scale/v2 训练**；若以后
用于训练，需要实现符号串动作和证书适配，不能只改文件名后直接输入训练器。
`--metamath <path>` 可额外写出完整独立 `.mm`，含全部结果及依赖。

深度把源断言作为单位，复用新引理时使用 `引理原深度 + 最深实参深度` 的保守上界。
它不展开源库已有 `$p` 的原始证明，也不是最短证明长度。标签预算限制单条 `$p` 的
直接证明；通过库中旧 `$p` 引用的展开总长度可能更大。完整依赖仍保留，没有将新引理
变成零成本公理。

## 验证与当前限制

回归覆盖符号串系统、空串、重复变量匹配、压缩证明保存/复用、交错 `$f/$e`、作用域、
非法证明拒绝、类型见证缺失、`$d`、可复现连续采样、默认入口不变，以及导出后重新解析。
独立核验工具：[generic_verify_smoke.py](../tools/generic_verify_smoke.py)。
它使用官方 C 程序，并可同时运行用户指定的官方 Python 验证器，保存完整日志。

```bash
python tools/generic_verify_smoke.py formal/peano.mm formal/peano-pa-plus.mm --metamath outputs/tools/metamath/metamath.exe --mmverify outputs/reference/mmverify.py --steps 250 --output-dir outputs/generic-verification
```

外部程序需要事先放在相应位置；工具不会自动下载。2026-10-10，种子 7、各 250 次尝试，
本机已有的官方数据库进行了以下 smoke 检查，两套外部验证器均接受全部新增证明：

| 形式系统 | 新声明数（含语法声明） | 无开放假设的声明数 |
| --- | ---: | ---: |
| Peano | 17 | 11 |
| PA+ | 22 | 16 |
| demo0 | 44 | 13 |
| MIU | 29 | 24 |
| HOL | 106 | 10 |

这共计 218 个新声明。使用的 `mmverify.py` SHA-256 为
`000975e614176f0cca49abbac50bbd26fb959013c6ea6cb8754d3ac049a4b6bc`。
原始记录位于忽略目录 `outputs/generic-verification/`，不会随 Git 提交。
这些结果是兼容性和证明正确性检查，不是采样质量、闭合率或训练收益的比较实验。

另对本机 `set.mm` 的 50,888 个断言、47,826 个已有证明完成加载验证；50 次生成尝试
产生 3 个新声明。官方 C 程序和 `mmverify.py` 均接受该源库及新增证明，共 47,829 个
`$p`。此次较大数据库检查的快照和日志位于 `outputs/generic-smoke/set/`。

后续优化应针对以下实际限制：

- 有预算的单向符号串匹配不是完整双向 word unification；歧义较多时可能先耗尽预算。
  匹配已接受的前提不做跨前提回溯，局部选择可能导致本可消除的假设留下来。
- 类型证明搜索只从已有节点或无 `$e` 的构造规则开始；复杂或带前提的类型推导需要先
  在前向过程中得到相应节点。搜索失败表示当前没有找到见证，不表示表达式不可证明。
- 符号串匹配对 PA+ 通常比专用 AST 更宽泛，不能把通用后端理解成性能升级。
  大库选择规则和桶内加权仍有线性开销；达到池上限后停止接纳，未实现档案换入换出。
- 缺少完整证明库的数据切分与目标隔离。如果源库含测试定理，其 `$p` 会正常成为可用
  规则；做模型评测前必须明确可用声明的时间/范围，不能把该场景当成无泄漏评测。

`match_states` 包含失败尝试的预算消耗；`matched_premises`、`reserved_premises`、
`unmatched_premises` 则只统计成功入库的规则前提槽位，不等于最终去重后的假设数量。
保留这些区别，再评估是否值得把此备用后端接入训练。
