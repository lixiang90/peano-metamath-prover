# 引理依赖、循环计算与首版边界

用户补充（2026-10-03）：引理引用既有引理可能诱发递归编码，形成参数共享的深层计算；首版应采用成熟策略，后续再实验。

## 依赖图不等于 Loop Transformer

证明 `L2` 使用 `L1`，意味着证明证书中存在依赖边，不必意味着神经编码 `L2` 时要再运行 `L1` 的编码器。只有当我们主动设计 `z(L2)=E(statement(L2), z(L1))`，才引入沿依赖图传播的神经计算。若依赖图无环、每个节点仅编码一次，这是拓扑顺序上的组合编码；Loop Transformer 通常指对同一隐状态重复使用共享 Transformer 块。二者可能结合，但不能由引理引用自动推出等价关系。

论文 *Compression is all you need* 以层级定义和证明宏讨论数学压缩，并分析库的依赖图。这支持探索可复用引理与库选择；它没有证明“递归神经编码优于声明编码”，也没有给出适用于本项目的训练稳定性保证。[原文](https://arxiv.org/html/2603.20396v1)

循环深度研究给出了值得后续实验的证据：共享层的重复计算可在某些推理任务上接近具有相同有效深度的非共享模型；recurrent-depth 语言模型也展示了增加测试时计算的可能性。它们的任务、数据和计算规模与小型 PA+ 证明器不同，不能直接迁移收益结论。[Saunshi 等，ICLR 2025](https://arxiv.org/abs/2502.17416)、[Geiping 等](https://arxiv.org/abs/2502.05171)

较新的 STARS 工作特别研究增加循环深度后性能退化的问题，采用稳定性正则与随机循环采样。这说明“增加引用层数”不能当作免费且单调改善的推理计算预算。[Yang 等，ICML 2026](https://arxiv.org/abs/2605.26733)

## 首版实际策略

- **只编码完整的引理逻辑签名**：结论、全部假设、变量类型和 `$d`。不把证明依赖展开进神经输入，不在 encoder 中调用 encoder。
- **独立因果编码**：每条引理由有限层 decoder-only Transformer 处理一次，末尾 summary slots 汇聚前文，再插入主模型。长输入明确拒绝，不能截掉假设或约束。
- **符号证明与神经表示分离**：库保存可重放证明；应用引理时展开/验证证明宏。只有符号内核能决定是否成立，向量相似度只指导选择。
- **当前批次使用当前权重**：联合训练时重算被读入引理的编码并保留梯度，不从持久缓存取旧训练向量。检索用 detached/frozen 的索引，记录权重版本；刷新前不能混用两个空间。
- **显式轨迹保持不变**：Agent 的动作、失败、读取和回退记录在文本上下文中。首版不引入 latent CoT、固定点求解或可变次数循环主干。

声明编码会舍弃引理“如何被证明”的结构信息；这是为了得到可测量的稳定基线，不是认定证明结构没有价值。前向证明的展开标签有硬长度预算，防止验证成本随嵌套引用失控。

## 训练困难及后续实验顺序

全递归联合训练可能造成依赖深度不定、共享祖先重复计算、长梯度路径和显存不可预测；缓存祖先向量又引入陈旧表征和截断梯度。若误允许当前引理引用自身，还会破坏证明的良基性。训练时浅依赖、测试时深依赖也是新的分布偏移。

建议按以下次序做独立消融，而不是在首版同时启用：

1. 声明编码基线：文本引理与 1/2/4 个向量槽比较，记录认证成功率、总 token、延迟和显存。
2. 有界一跳依赖：只把少量已证父引理的冻结表示加入声明编码，父节点 stop-gradient；仍检查 DAG，无环且时间上早于当前节点。
3. 拓扑共享编码：每个祖先每批只算一次，深度上限 2/4，刷新缓存；比较固定父表示与有限深度联合反传，评估 OOD 深度。
4. 独立循环深度实验：显式设定训练循环次数分布、测试上限、停止条件、梯度截断/检查点策略。比较相同 FLOPs 的非循环模型；只有取得稳定且可复现的认证收益后再考虑合入默认配置。

后续验收应固定数据、划分、验证器和搜索预算，分别报告条件引理正确使用率、检索命中率、proof reuse、验证耗时与收益。观察到 CE 下降、向量更接近或隐藏状态收敛，均不足以证明数学能力提高。
