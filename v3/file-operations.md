# PA+ 模型可以读写哪些文件

一题配一个符号工作区。模型可以把稍后要用的公式留在草稿里，经过几个子目标后再按行取回，也可以改写自己的证明计划。Rethlas 的公开数学研究流程给每题约定了 `blueprint.md` 和 `blueprint_verified.md`，分别承载可修改的证明草稿和通过其验证流程的版本。PA+ 可以借鉴这种固定地址和内容分工，并让 Metamath 承担形式证明的验算。[Rethlas 作者的工作协议](https://github.com/frenzymath/Rethlas/blob/main/agents/generation/AGENTS.md)

## 三个操作和五个文件名

| 控制 token | 参数 | 行为 |
| --- | --- | --- |
| `FAPPEND` | 文件，一条记录 | 在末尾新增，返回从 0 开始的行号。 |
| `FWRITE` | 文件，行号，一条记录 | 替换指定的已有记录。写入空文件的第一条记录用 `FAPPEND`。 |
| `FREAD` | 文件，起始行，最多读几行 | 返回完整记录和下一页的起始行。`next` 为空表示已经读到末尾。 |

| 文件名 token | 内容 | 由谁写入、保留多久 |
| --- | --- | --- |
| `FILE_PROBLEM` | 原题结论、各个假设、变量类型和 `$d` 相异对。 | 引擎在开题时固定，一题内可反复读。当前子目标仍在正常的引擎反馈中。 |
| `FILE_PLAN` | 有顺序的子命题清单，每行一条 `wff`。模型可以重排思路或替换其中一步。 | 模型可改，随当前分支提交或回退。清单本身不新建证明义务。 |
| `FILE_SCRATCH` | 一行一个 `term` 或 `wff`，可记一段长算式、一个候选引理或两个不同的猜想。 | 模型可改，随当前分支提交或回退。 |
| `FILE_TRIALS` | 当前路径上已经执行的试探。记录父状态的题内短编号、动作、观察结果、关闭目标数和 `COMMIT` 或 `BACKTRACK` 决定。同一父状态重复试探使用同一编号。未决试探的决定为空。 | 引擎追加。回退后仍能读到尝试摘要。 |
| `FILE_LIBRARY` | 当前状态向模型公开的库引理 ID 和陈述。 | 引擎从冻结库生成只读视图。切换目标后应从头分页，以引理 ID 作为持久引用。 |

操作和文件名分别占一个 token，行号及内容由既有符号组合而成。同一个 `FREAD` 可读五种文件。原有的 `READ l` 提案按引理 ID 看完整陈述，`FREAD FILE_LIBRARY 0 4` 则是浏览当前可见索引。文件行号指本版本中的位置。真正使用某条公式还要对当前目标显式发出 `HAVE` 或 `USE`，重新检查作用域和证明义务。

词表在原来的 701 项末尾追加这 8 项，共 709 项。`FREAD`、`FWRITE`、`FAPPEND` 编号为 701–703，以上五个文件名依表中顺序编号为 704–708。`FREAD FILE_SCRATCH 0 1` 的正文从 22 个 token 缩短到 7 个，包含分隔符和数值参数。历史 701 项词表的编号及指纹可用 `file_tokens=False` 复现。[词表](tokenization/pa_symbols.py) · [兼容性测试](tokenization/test_pa_symbols.py)

## 列目录与按内容查找

五个文件名和读写权限由协议固定。建议在开题、上下文恢复和回退后的引擎反馈里附上可变文件的行数。这样模型能知道哪本笔记有内容，追加时已有的行号回执可用于直接读取。等模型能创建或挂载命名文件时，再引入可分页的 `FLIST` 枚举实际文件。

对已经忘记行号的笔记，建议复用控制符提案中的 `SEARCH`，按首个参数选择搜索范围。`SEARCH FILE_SCRATCH term + 0 x0` 在当前分支的草稿里找含有这个子项的记录，可以找回 `wff = + 0 x0 x0`。文件搜索返回少量行号和短片段，需要全文时可用 `FREAD` 读取。`SEARCH g0 φ` 则按目标和公式检索冻结的已证引理库，返回可交给 `READ` 或 `USE` 的引理引用。首版文件查询按完整符号或解析树中的子式匹配，保留操作数顺序。可先在 `FILE_SCRATCH` 和 `FILE_PLAN` 上试验，调用、返回 token 和搜索耗时计入同一题的预算。Lean 的 Loogle 也提供按常量和子表达式查找数学声明的接口。[Loogle 查询说明](https://loogle.lean-lang.org/)

用 35 条 PA+ 目录陈述按原顺序模拟一册笔记，实际解析后查询完整子式 `wff sqrtinterval x0 x1 x2 x3 x4`，只命中行号 33。从头每次顺读 8 行，第五页才出现该陈述。已有的读写证明轨迹只用了一行草稿。这两种长度适合分别检验直接读取和按内容定位。目录摘要与文件搜索在此作为设计提案。[PA+ 目录](../formal/pa-plus-definitions.json)

## 一段实际运行过的读写

原题是 `(0 + n) + 1 = S(n)`。先记下有用的引理 `0 + n = n`，然后到试探分支考察另一个猜想。以下是同一条手工指定轨迹的紧凑表示，箭头右侧是引擎返回的数据。

```text
FAPPEND FILE_SCRATCH wff = + 0 x0 x0   → 0
TRY HAVE g0 = 0 x0
FWRITE FILE_SCRATCH 0 wff = 0 x0
BACKTRACK
FREAD FILE_TRIALS 0 1                   → HAVE g0 (= 0 x0), UNKNOWN, BACKTRACK
FREAD FILE_SCRATCH 0 1                  → wff = + 0 x0 x0
APPLY HAVE g0 = + 0 x0 x0
APPLY INDUCT g1 x0
```

试探中的改写已经撤销，尝试的经过仍可查询。`UNKNOWN` 表示有限求解未得到证明。读回好猜想后，`HAVE` 仍然阻塞原目标的续接，直到归纳补齐引理证明。导出的原题证书与此前经官方 Metamath 验证的文件逐字节相同。上面四次文件调用共计入 157 个命令与返回 token。仅试探记录使用题内状态编号这一项，就比回传完整哈希和原字段名少用 76 个 token。[逐步读写记录、证书与官方验证器指纹](results.json)

## 接口边界与训练对照

在仓库根目录运行 `python -m pytest -q v3/test_proof_files.py::test_published_file_trace_and_certificate` 即可逐步重放上面的记录。测试会核对每次回复和 I/O token 数，重新导出证明，并按统一的 LF 换行与经认证的证书比较 SHA-256。[回放测试](test_proof_files.py)

参考实现给每个单题交互分配一组内存文件。宿主把文件命令的返回值放进 `ENGINE` 段，模型只产生 `MODEL` 命令。普通提示保留活动证明状态，草稿内容按读取请求进入提示。写入时检查前缀表达式和可见变量。分支内可以写下错误猜想，已证引理的跨题准入仍由冻结库及证书流程处理。

如果将来需要关掉进程后接着做同一道题，宿主可以按题目和库快照保存公开交互、可写文件、未决试探的父本以及已用预算，恢复时核对证明状态。这样可在同一文件协议下换用磁盘存储。

`TRY` 快照包含两本可写文件。`COMMIT` 保留新版本，`BACKTRACK` 恢复旧版本。调用和 token 开销归本题，回退不退还。原型的可调总额默认为 64 次、8,192 个文件 I/O token，每次最多读 8 条记录。每本可写文件最多 64 条，每条最多 256 个符号 token。这些是实验起始值。返回预算不足时写入不会生效。[参考执行器](proof_files.py)

要检验模型是否真正用到了文件，可以从自生成证明图中挑出两个相隔多个步骤、共同使用一个中间引理的子目标。保留当前目标及假设，让引理第一次出现的对话退出短上下文。对同一批题比较“只给相同的只读视图”和“再开放可写计划及草稿”，匹配上下文、总推理 token 和墙钟预算，把读写也计费。先看配对的认证题数，再查哪些成功证明实际使用了窗口外读回的引理。

如果后续要训练“修改第几步后重新验算整段证明”，可再增设 `FILE_SCRIPT` 和 `CHECK_SCRIPT`。前者保存动作序列，后者从指定的证明状态重放并报告首个失败行。这两个名字属于后续设计，当前实验词表和参考执行器使用上面的八项。

在仓库根目录运行以下用例可复现读写、提交、回退和读回引理后构造证明的过程。当前 v2.1 训练及搜索入口尚未接入文件动作。

```powershell
python -m pytest -q v3/test_proof_files.py v3/tokenization/test_pa_symbols.py
```
