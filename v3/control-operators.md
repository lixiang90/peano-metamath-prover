# PA+ 证明器的控制符和操作符

建议 v3 先保留 v2.1 的五个证明动作和四个交互命令，再开放 `PROPOSE`、`TEST`、`SEARCH`、`READ`。最值得先做的是让模型自己写 `HAVE` 的公式参数。下面的新增接口是设计提案，已运行的实验使用现有执行器。

文件读写采用单独的 `FREAD`、`FWRITE`、`FAPPEND`，可在一题中保存公式和更改计划。它们已经加入 v3 词表并有独立的可执行参考实现。[符号文件协议](file-operations.md)

## 现在的符号都由谁使用

| 位置 | 当前符号 | 实际作用 |
| --- | --- | --- |
| 序列和编码 | `PAD`、`BOS`、`EOS`、`MEM`，以及 v3 的 `JOIN` | 前三项管填充和序列边界。v2 曾用 `MEM` 标记注入引理向量的位置。符号版用 `JOIN` 还原两个形式符号紧贴的拼写。 |
| 轮次 | `STATE`、`ACTION`、`ENGINE`、`MODEL` | A 用前两个组织状态和候选动作的前缀，B/C 用后两个标记谁在说话。角色标记由宿主写入。 |
| 证明状态 | `OPEN`、`ROOT_READY`、`UNKNOWN`、`UNKNOWN_WITHIN_BUDGET` | 引擎报告仍有目标、本地已构造根证明、未得出结果、预算内未得出结果。根证明就绪后由官方验证器验算，如有未提交的试探则先提交。 |
| 数学动作 | `INDUCT`、`HAVE`、`STRENGTHEN`、`USE`、`UNFOLD` | 依次用于归纳、引入待证引理、证明更强命题及其蕴涵、套用库定理、展开当前目标外层所支持的定义。每个动作都指定目标。 |
| 执行和回退 | `APPLY`、`TRY`、`COMMIT`、`BACKTRACK` | B/C 用 `APPLY` 包一条数学动作。C 还可短试一次，再提交或恢复。A 直接选数学动作。 |
| 已登记的其他字面项 | `READ`、`feedback`、`scratchpad`、`true`、`false`、`null`，以及 39 个字段键 | `READ` 在 701 项词表中占一项，v2.1 的解析器却没有这个命令。其余是模式、值及字段。举例说，`"memory":` 是字段，并无写记忆的权限。 |

701 项是 v3 符号原型的大小，v2.1 的实训模型仍按字节读这些拼写。v2.1 的执行器还会回送 `TRY_RESULT`、`PROOF_CONSTRUCTED` 等值，原型会用多个 token 表示这些值。[v3 词表](tokenization/pa_symbols.py) · [v2.1 数学动作](../v2_1/pa_prover_v21/strategy.py) · [轮次、结果及短试探](../v2_1/pa_prover_v21/interaction.py) · [模型候选评分](../v2_1/pa_prover_v21/policy.py)

更早的 v2 有独立的前向执行器，接受 `APPLY`、`PROPOSE`、`SAVE`、`SEARCH`、`READ`、`USE`、`BACKTRACK`、`SNAPSHOT`、`FINISH`。其中 `APPLY` 按 Metamath 规则、替换和前提构造事实，`PROPOSE` 只登记猜想，`SAVE` 给已证明的事实起局部名字。v2.1 转向带子目标的逆向搜索，当前会自动取最多 8 条相关库陈述放进观察，也会自动做便宜的逻辑分解和经典闭包。把主动检索接回 v3 时可以复用这些部件。[v2 前向执行器](../v2/pa_prover_v2/agent.py) · [v2.1 候选和经典闭包](../v2_1/pa_prover_v21/search.py) · [引理检索和实例化](../v2_1/pa_prover_v21/library.py)

## 通用数学模型提供的三个参照

- DeepSeek-Prover-V2 的冷启动管线让通用 DeepSeek-V3 把难题拆成带具体公式的 Lean `have`，再逐一填好子证明。对应的 PA 能力是输出一个类型正确、可以递归求证的中间命题。[论文 §2.1](https://arxiv.org/html/2504.21801v2)
- o3/o4-mini 的数学评测展示了模型在推理中调用 Python 的用法。o4-mini 在允许 Python 的 AIME 2025 上报告了 99.5% pass@1。这里借鉴的是用计算来检查一个想法，然后依据返回值做下一步选择。PA+ 的可复现实验可以从自然数求值开始。[OpenAI 原始评测](https://openai.com/index/introducing-o3-and-o4-mini/)
- DeepSeek-R1-Zero 在训练中出现过重审原先步骤、改走另一条路线的行为。我们把一次这样的决策具体化为试探、读取执行结果、接受或恢复旧状态。论文观测的是模型行为，下面的操作符是针对 PA 的设计推论。[DeepSeek-R1 原论文 §2.2.4](https://arxiv.org/pdf/2501.12948v1#page=8)

## 建议的首版接口

下表的 `g` 指当前活动目标，`d` 指当前作用域的猜想，`l` 指冻结库中的引理引用，`φ` 是前缀公式。序号和公式都是参数。当前证明器支持的公式片段、变量类型、量词绑定、开放假设及规则实例化时的 Metamath 相异条件都由程序检查。

| 模型写出的命令 | 引擎执行和返回的结果 |
| --- | --- |
| `PROPOSE g φ` | 解析模型自己写的公式，在本分支的草稿中登记为 `d`。可同时保留几种想法以供比较。逻辑事实表维持原内容。 |
| `TEST g d` 或 `TEST g φ` | 对可计算的算术片段，在小预算内寻找满足当前假设且使猜想为假的赋值。返回 `COUNTEREXAMPLE` 和赋值，或 `NO_HIT` 和实际检查的范围、满足假设的赋值数。无法计算假设或超出预算时返回相应的 `UNKNOWN`。有限试值仅产生观察。 |
| `SEARCH g φ` 或 `SEARCH g d`，`READ l` | 模型可用目标、子式构成的公式或草稿的公式主动检索。搜索返回有界的引用和结论摘要。`READ` 按需返回完整陈述、前提、类型和相异条件。已经看到足够信息时可直接 `USE`。 |
| `APPLY HAVE g φ` 或 `APPLY HAVE g d` | 建立引理义务和用它继续证明原目标的义务。引擎把后者阻塞到前者确实证成。允许直接提供新公式，只在需要记住或比较猜想时才经过 `PROPOSE`。 |
| `APPLY INDUCT g x`、`APPLY STRENGTHEN g φ`、`APPLY UNFOLD g`、`APPLY USE g l` | 分别建立归纳基与归纳步，建立 `φ` 和 `φ ⇒ 原目标`，展开定义，或核对库引理并生成剩余前提。归纳原有的 `generalize` 参数继续可用。 |
| `TRY 动作`，然后 `COMMIT` 或 `BACKTRACK` | 试探时执行同样的数学动作，并得到预算受限的闭包反馈。首版保持一层未决试探。回退恢复目标、假设、局部引用和新鲜变量，保留尝试记录及已消耗的预算。 |

**消息与事实的边界。** 宿主依次写入 `ENGINE` 和 `MODEL` 段首，每条模型命令用换行结束。从各段真实 token 数生成动作监督掩码。引擎可用单个 `RESULT` 加命令名标记回复。建议把反例、未找到反例、无效命令 `INVALID`、最终证书通过 `CERTIFIED` 登记为引擎结果。生成命令时按当前角色和状态限制可用符号。短试探里的 `ROOT_READY` 仍需提交，最终成功只由原题的官方 Metamath 验证产生。后续更改词表时应固定旧编号、追加新编号并更新指纹，当前原型会按拼写排序重建编号。

**可生成的参数。** 当前策略只给手写枚举器返回的完整候选评分。v3 可以先保留这条便宜路径，再给 `HAVE` 或 `PROPOSE` 分配少量自由提案。按前缀语法和期望类型逐项生成，量词变量取自合法作用域，并对生成长度、候选数和总搜索时间设预算。用训练证明图的中间节点做“恢复被隐藏引理”的样本，输入只给原状态中当时可见的信息。新得引理以本次库快照的引用传递，局部草稿在回退时按作用域撤销。

**两种寿命的记忆。** 每个本地已证事实可以有一个分支内引用，连同它所依赖的假设一起使用。要供后来的题检索，沿用现有库的准入方式，解除开放假设、核对原陈述、验证完整证书后再加入下一份库快照。这样同一个新引理在未来许多题中都可被 `SEARCH` 找到。[现有引理库的核验与准入](../v2_1/pa_prover_v21/library.py)

**可后置的动作。** `REWRITE g l 方向 位置` 适合模型必须选择某个子式和改写方向的题，需能用等式或已证等价重建证书。`WITNESS g 项` 适合 `∃x P(x)`，会生成代入后的 `P(项)` 义务，并要求无捕获代入和存在引入证书。PA 的形式库有存在量词，v2.1 的策略入口目前也依赖 ATP 翻译器，它尚未接收 `exists`。`INTRO`、合取拆分以及根目标验算可先由引擎自动办理。写出“我在反思”的标签，可以直接由一条携带公式的试探或一次有反馈的回退取代。[当前 ATP 片段](../v2_1/pa_prover_v21/atp.py) · [PA 量词定义](../formal/peano.mm)

## 一道实际通过验证的例子

目标是任取自然数 `n`，证明 `(0 + n) + 1 = S(n)`。在现有 v2.1 执行器上，第一次经典闭包留下了这个目标，候选生成器给出 17 个动作，其中 8 个是 `HAVE`。想用的辅助等式 `0 + n = n` 没有出现在这 8 个里。

```text
APPLY HAVE   g0  = + 0 x0 x0
APPLY INDUCT g1  x0
```

实验脚本手工给出这两个动作，以原来的接口调用执行器。第一步确实阻塞了原目标的续接，第二步把引理拆成归纳基和归纳步。经典闭包补完剩余推导，最终证明依赖这条引理，导出的证书通过了官方验证。这个例子定位的是候选边界，原题还可能有其他证明。[候选计数、实际使用的引理与证书指纹](results.json) · [实验脚本](probe_lemma_action.py)

同一道题还可以说明拟议中 `TEST` 的用途。现有枚举器确实给出了 `0 = 0 + n` 这个候选。取 `n = 1` 就得到 `0 = 1`，引擎可以返回具体反例，模型据此放弃这个草稿。对于 `0 + n = n`，试完若干小数值只能返回 `NO_HIT`，引理义务仍交给上面的归纳证明。

## 怎样判断模型学会了这些操作

在 11 月冻结训练分片中，B 的 116 条成功交互轨迹有 2 条含模型命令，均为 `APPLY INDUCT`。C 的 114 条中只有 1 条含模型命令，内容是 `TRY INDUCT → COMMIT`。这批 C 成功轨迹中的 `BACKTRACK` 次数为零。该次冻结库也是空的。仓库的独立测试则能先强制一个无用的 `HAVE`，再回退并完成经认证的证明。[历史逐组统计与冻结库规模](results.json) · [现有回退与证书测试](../v2_1/tests/test_interaction.py)

第一轮对照只改变 `HAVE` 的参数来源。在相同题、库、训练数据、总候选额度、模型配置和搜索预算下，比较枚举参数与“枚举加按类型生成”的参数。两组都训练并计入提案耗时，同时和同预算启发式比较。主指标是逐题配对的官方认证数，同时数出多少题的最终证书实际使用了枚举器以外的引理。然后分别接入 `TEST` 和主动检索，在有真反例、非空冻结库的题上单独检验其增益。自生成的轨迹应包含试错后恢复、找到已证引理再复用的实例。工具调用次数和草稿长度只用于分析。
