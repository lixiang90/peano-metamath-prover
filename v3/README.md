## 先看一道真实的题

11 月留出集的 `p0004` 写作 `|- = x0 * S 0 x0`。这里用前缀记号，`S(0)` 表示 1，整句读作“对任意自然数 n，n = 1 × n”。它经历了三个不同的过程。

1. **出题。** 生成器枚举由 0、一个变量、后继、加法和乘法组成的小表达式。在 n 取 0 到 5 时，表达式 n 和 1 × n 给出相同的六个值，于是可以把它们组成待证等式。此时只有一道猜想。
2. **选路。** 经典求解器先尝试化简。卡住以后，A 模式列出 13 个合法候选，手写顺序的第一项和模型评分的第一名都是“对 n 作归纳”。基础情形是 0 = 1 × 0。归纳步里，乘法的递推式把 1 × S(k) 化为 1 × k + 1，归纳假设把它化为 k + 1，也就是 S(k)。
3. **交卷。** 高层策略只选了一次动作。符号程序构造基例和归纳步的证明，消去局部假设，展开所需的等式与逻辑推理，最后写出原题的 Metamath 证书。这份实际导出的片段含 6,554 条 `$p` 声明，含辅助结论及最终定理。官方验证器可以逐条检查。这里“一次决策”和“证明多长”量的是两件事。[乘法与归纳公理](../formal/peano.mm) · [该题的候选数、搜索步数及证书声明数](results.json)

## 形式系统如何约束模型

Metamath 规定怎样合法地套用一条规则。项目的 PA 库规定可以谈论哪些自然数命题，以及能用哪些逻辑和算术公理。表达式分类型，例如 `term` 是项，`wff` 是公式。给公式加上 `|-` 就表示断言它成立。规则可以带前提，替换还必须遵守变量类型和 `$d` 的变量相异约束。例如局部假设 `a=b` 可以推出 `S(a)=S(b)`。如果用了这个假设，定理就要带上它，或在消去假设后写成蕴含。[基础形式库](../formal/peano.mm) · [证明组合与作用域](../docs/architecture.md)

形式库从 PA 扩展到数论，再到 PA+。PA+ 的 68 个新谓词各有旧语言中的定义，例如 `positive(a)` 展开就是 `0<a`。搜索可选用 136 条有证明的展开／折叠规则，导出证书时再把它们还原为源库推理。目录另列了 35 个 `statement`，表示系统能写出这些问题，解题数须另行测量。实验的训练题和证明可由程序生成。公理、定义、候选文法和启发式来自人的设计，部分早期检查点训练时还看过命名目标提示。[PA+ 定义目录](../formal/pa-plus-definitions.json) · [定义与证书](../docs/pa-plus-certification.md) · [旧检查点的提示来源](../docs/v21-atp-evaluation.md)

## 数据从哪里来

**先证明，再把结论当题。** v1、HTPS 和 v2 共用的随机证明图从源规则出发，抽一条推理规则，再找能与它的前提匹配的旧节点。“合一”就是寻找一组一致的替换，让公式形状对得上。例如用加法公理得到 `x=x+0`，用后继同余和分离规则就能得到 `S(x)=S(x+0)`。父节点和替换一起留在图里，后来可以重放整条证明。多个前提如只接上一个，其余前提仍写在新定理的条件里。默认约 90% 的尝试做组合，约 10% 做小表达式实例化，去重和资源限制会改变实际入库比例。早期 Scale 实验还用过对少量模板反复换项的扩增法。[随机证明图算法](../docs/random-proof-graphs.md) · [生成实现](../src/metamath_generator/random_graph.py)

**先提出猜想，再寻找证明。** v2.1 高层数据混入前例那样的算术猜想。程序先按规范化声明、结论、公式骨架和证明图来源分组，再让教师求解。经典求解、启发式、随机试跑或冻结模型得到的成功轨迹，记录了在这个状态有哪些动作曾走通。超时的尝试记作预算内未完成。未解猜想仍留在评测分母。教师的参考证明对评测搜索隐藏，历史证明只能经已认证、冻结的引理库复用。[猜想文法](../v2_1/pa_prover_v21/data.py) · [分组、教师与轨迹采集](../v2_1/pa_prover_v21/curriculum.py)

## 各个版本让网络学什么

| 版本 | 网络看到什么、输出什么 | 怎样得到一份证明 |
| --- | --- | --- |
| v1 | 编码器读目标、前提和变量，解码器据此预测下一条底层规则和替换。另有候选评分头和状态价值头。 | 最优优先搜索或 MCTS 在多目标状态中试走。启发式也会实际执行候选，给能立刻收尾、减少待证目标、留下可直接关闭目标的动作加分。 |
| HTPS | 用策略给候选排序，用价值估计给开放目标打分，可选提议中间引理。 | 共享重复子目标。一道题可以任选一条适用规则，一条规则产生的所有前提则都必须证明。这就是 AND/OR 证明图。 |
| v2 | 自回归 Transformer 同时读目标和动作历史。另一个因果编码器把读到的已证引理声明压成向量，放回主模型的上下文。 | Agent 能执行 APPLY、查库、READ、USE、保存草稿和回退。要使用引理，还要证明它所需的前提。v2 的小规模验收中，SFT 模型在 5 道测试题上认证了 3 道。 |
| v2.1 高层策略 | 独立的字节级自回归 Transformer 读取剩余目标、前提、类型、历史和预算，对有限的候选命令逐条评分，价值头估计完成机会。引理以文本供给。 | 先交给经典求解，遇阻再选归纳、提出引理、加强命题、用引理或展开定义。提出引理会增加证明义务。A 用状态和动作历史，B 加入真实执行反馈，C 再允许短试探、提交或回退。 |

v2.1 有两个不同的评测入口。早期入口比较旧 v1 模型和 Vampire。纯 ATP 组先把受支持的一阶公式交给 Vampire，获得证明声称后再从 PA 公理重建证书，由官方 Metamath 检查。后来的高层入口先尝试内部证明构造，也可调用 Vampire。手写和学习策略共用经典求解器、候选生成器和引理库。A 的手写策略按枚举顺序给候选分配递减权重，普通归纳排在多数引理提议之前。传统归纳组则直接尝试在原命题上作归纳。[v1 策略](../src/neural_prover/search.py) · [HTPS](../docs/htps-design.md) · [v2 与验收](../v2/docs/validation.md) · [v2.1 策略与搜索](../v2_1/pa_prover_v21/search.py)

**训练信号也逐代改变。** 早期 v1 模仿参考动作，辅以候选排序和价值损失。2026-10-11 起，v1 的新图语料会重放完整证明，记录每一步所有待证目标，给几条都能走通的候选同时标正例，并按剩余步数给价值目标。由于训练数据会强制加入参考动作，检查推理能否找到这个动作时，要查看枚举器未经补入的候选。[完整轨迹训练](../docs/proof-training-trajectories.md) · [候选监督实现](../src/neural_prover/trajectories.py)

v2/v2.1 的下一 token 预训练（NTP）学习给定前文时下一个符号是什么，监督微调（SFT）学习在具体状态怎么行动。v2.1 对同状态下多个已获证书的动作奖励其总概率，并用独立试跑的预算内成功率训练价值头。B/C 的轨迹微调只监督模型发出的命令，环境反馈用作输入。可验证奖励强化学习（RLVR）从同一道题采样多次，用整题证书给奖励。同组试跑有成有败时，学习器才有相对优势可学。专家迭代还可以让已训练策略参与下一轮造数据，把已证训练引理加入下一轮库。11 月的 A/B/C 实验实际只用了 NTP 和 SFT。[v2.1 训练实现](../v2_1/pa_prover_v21/training.py) · [A/B/C 交互协议](../docs/v21-symbolic-scratchpad.md)

## 下一项值得一起做的实验

1. **在开发集上制造真正需要选路的状态。** 给自生成等式引入两个可选的归纳变量，或让同一个中间结论在不同证明中可复用。对同一状态轮换强制首步，每个分支用相同预算，保存完整成功证书和未完成原因。统计有几道训练题出现“首选没解出、另一候选解出”，以及多少成功轨迹需要两次以上的高层决策。若仍接近零，先改出题文法或候选覆盖。
2. **只改数据，测模型是否真的学会排序。** 固定 A 架构、推理候选、引理库和训练预算，对照原采样与增加分歧状态后的采样。用强制首步的成功集合测前几名能覆盖多少已知解，同时记录候选为空的次数，以及枚举、网络打分、经典求解与验证各自的耗时。分支没在预算内走通，只能作为这份预算的观察。
3. **用新的留出题判断能否超过基线。** 在教师搜索前冻结多个生成种子、结构族和图来源，保留简单题以及教师未解题。手写、随机、模型和传统归纳用同一墙钟预算，以官方认证的整题数为主指标，配对报告双方独有的题、直接由经典求解完成的题及超时原因。另做等展开次数对照能看出排序收益是否被打分开销抵消。11 月的 36 题留作开发诊断，新留出集用于检验改进。
